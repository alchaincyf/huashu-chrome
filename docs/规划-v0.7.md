# v0.7 规划：agent 要的是状态，我们给的是动作

## 一、先说结论

v0.5–v0.6 那一批（支付闸门、凭据脱敏、ref 稳定、fill 效果证据、审计配对……）
是把**已经在说的话改准**，量级大概 15%–25%。它们都该做，但**加起来也不是体验翻倍**。

真正的杠杆有三条，都不在那一批里。它们指向同一件事：

> **agent 需要的是「状态」，产品给的是「动作 + 变化量」。**

## 二、证据：真实 agent 到底在干什么

按 `client` 字段拆审计日志，9283 行里只有 **514 次来自真实 agent**（`claude-code`），
其余是测试夹具 3003、cli 854。

⚠️ 样本局限先说清楚：这 514 次分布在 4 个会话，其中一个法签申请站的会话占 274 次，
偏得厉害。但这是唯一的真实使用数据，而它讲的故事非常一致。

```
eval 183 (35.6%)  navigate 60  click 52  tabs 38  snapshot 33
query 32  read_text 31  wait 26  network 12  screenshot 12
fill 8   act 8 (1.6%)   scroll 6
```

最常见的相邻二元组：**`eval → eval` 93 次**、**`click → eval` 24 次**。

### 183 次 eval 里，129 次（70%）在「看」

取文本/HTML 77 次、查元素属性 52 次，写操作只有 34 次。几条真实的：

```js
JSON.stringify({chk: [...document.querySelectorAll('.ui-chkbox,[role=checkbox],.ui-chkbox-box')]
  .map(x => ({cls: x.className, checked: x.className.includes('ui-icon-check')}))})

[...document.querySelectorAll('input[name="is_author"]')].map(r => ({value: r.value, checked: r.checked}))
```

**这不是 agent 在炫技，是 snapshot 回答不了它的问题。**
snapshot 是一份「可点清单」，而 agent 要的是「状态读数」。

129 次 eval，每一次都是一个完整的模型回合。**这是当前最大的一笔回合支出。**

## 三、三条杠杆

### A：`act` 不能返回观察结果 —— v0.4 只做了一半

v0.4 整版为 `act` 而建，规划第一句写着「10 倍体验就藏在这里」。
真实 agent 用了 **8 次（1.6%）**，7/8 成功——**不是不好用，是不被想起来。**

三个可查的原因，前两个 v0.6 已经修掉：

1. ~~`fill` 在 act 里必然报「没有可归因的变化」，批处理停在第一步~~（v0.6 修）
2. ~~act 停下来时不说为什么~~（v0.6 部分修）
3. **`act` 执行 N 步，只在末尾给一份快照。**

第三条是真杠杆。agent 的循环是「看 → 决定 → 看」，不是「做 → 做 → 做」。
中间的「看」拿不到，它就只能一次一个动作地回到模型——而那正是 act 要省掉的东西。

**要做的**：`act` 支持 `read` 步骤（读某个 ref 的文本/属性/值）和 `assert` 步骤
（条件不满足就停下并说明），让批处理带着中间观察结果回来。
现在下沉到扩展层的只有「执行」，这一步是把「观察」也下沉。

### B：快照在系统性地丢元素

`content.js` 里这一行：

```js
if (!name && role === 'button') continue;   // 无名按钮多半是装饰性图标，滤掉省 token
```

而 `roleOf` 的兜底分支把所有非语义元素都归为 `button`。于是
`<div class="ui-chkbox">`（PrimeNG 自定义 checkbox：无 role、无名字、
靠 `cursor:pointer` 进的候选池）**在快照里根本不存在**。
图标按钮、自定义开关、卡片上的「×」，同一条路消失。

agent 看不见它，只能写 querySelector 去摸——上面那 129 次 eval 里，
相当一部分就是在摸这些看不见的元素。

**要做的**：无名元素不再静默丢弃，给一个可辨识的标识
（`data-testid` / `#id` / 首个 class / 最近的文本）。
自定义 checkbox 的选中态要报出来（`.ui-icon-check` 这类靠 class 表达的状态）。

⚠️ **这条要小心 token 膨胀**：装饰性图标真的很多。
`collectCandidates` 已经有 `weak` 标记（纯 `cursor:pointer`、无 onclick / tabindex / role），
可以拿它当分界线——但 PrimeNG 那类用 `addEventListener` 绑事件的控件也是 weak，
一刀切会漏掉它们。**这里需要真实站点上的实测，不能凭空定规则。**

### C：效果证据答非所问

`click → eval` 24 次：每两次点击就有一次靠 eval 去核实。
这是 v0.3「效果证据」的失败信号——它做出来了，但回答的是「变没变」，
而 agent 问的是「变成我要的样子没有」。「DOM +12 节点」告诉不了它
「那个复选框现在勾上了吗」。

**要做的**：`expect` —— 动作里可以声明期望
（`{checked: true}` / `{name: "已关注"}` / `{gone: true}`），
扩展侧在 settle 窗口内验证，不满足就明说。
它同时是 A 里 `assert` 的底座，也让效果证据从「一段描述」变成「一个判定」。

## 四、为什么这三条是同一件事

它们分别对应状态的三个时态：

| | 问题 | 杠杆 |
|---|---|---|
| 现在 | 这一页现在是什么状态 | B |
| 将来 | 我要它变成什么状态 | C |
| 中间 | 连着做几步时怎么读状态 | A |

补齐这三条，「登录后台 → 找到内容 → 改标题 → 保存」才真正从 8 次调用降到 3 次——
那是 v0.4 规划里承诺过、但只兑现了三分之一的数字。

**如果只能做一件事：B + A。** 它们直接打在 129 和 93 这两个最大的回合池上。

## 五、不做什么

- **差分快照**（只回相对上次的变化）。测过：连续两次快照有 68% 的行完全相同，
  看着诱人。但快照本来就只收视口上下几屏内的元素，滚动一下集合就大变，
  差分在最需要它的长列表场景里恰好失效；而且 agent 的上下文一旦被压缩，
  它就没有「上次」可比。**先做 B——把每一份快照的信息密度提上去，
  比省掉重复的部分更值。**
- **强制 `snapshotId` 必填**。协议文档写着「click/type/select 必须带 snapshotId」，
  代码里是可选的。看着像 bug，其实不该照文档改：`find` 和 `selector` 按设计
  就不依赖快照，`key` 不带 ref 时打给焦点元素——加 required 会把这些正常用法全废掉。
  v0.6 已用更便宜的办法覆盖了真实风险（编号跨快照稳定 + 名字比对 + 回执印实际命中的元素）。
  **该改的是文档。**
- **站点白名单**。见 README，已定为不做。
