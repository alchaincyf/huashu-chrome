## 关键来源

- Claude in Chrome：https://code.claude.com/docs/en/chrome （API key / Bedrock / Vertex / Foundry 一概不行；遇登录页/验证码暂停）；https://claude.com/claude-in-chrome （GA，全部付费套餐）
- Codex for Chrome（商店名「ChatGPT」）：https://learn.chatgpt.com/docs/chrome-extension ；「Browser isn't available in Codex CLI or the Codex IDE extension」https://learn.chatgpt.com/docs/browser ；CLI 拿不到扩展后端 issue 仍 open https://github.com/openai/codex/issues/26820 ；商店文案「work in the background without ever taking over your active browsing session」
- playwright-mcp：https://github.com/microsoft/playwright-mcp ；扩展模式 https://github.com/microsoft/playwright/tree/main/packages/extension （「Each one gets its own tab group … a tab can belong to a single client at a time」）；扩展 v0.4.0 2026-09-02
- chrome-devtools-mcp：autoConnect（Chrome ≥ M144，chrome://inspect/#remote-debugging 逐次授权）https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/docs/advanced-usage.md ；https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect ；issue #2283 默认 profile autoConnect 失败 closed as not planned
- Browser MCP：https://github.com/BrowserMCP/mcp （pushed_at 2025-04-24，停更约 16 个月；单槽 `killProcessOnPort`；扩展闭源 issue #72；无 network issue #39）
- Browser Use：https://docs.browser-use.com/open-source/customize/browser/real-browser （库要先关 Chrome）；Harness https://github.com/browser-use/browser-harness （SKILL.md：「treat local Chrome as one shared browser lane」「Two agents … can race」；`BH_DOMAIN_SKILLS=1` 默认关；🐴 标题标记）
- computer-use：Anthropic `computer_toolset_20260801` https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool （工具定义约 4,500 input tokens）；Anthropic 另有独立 browser use tool（含 read_network）；OpenAI Operator / ChatGPT agent 已下线 https://help.openai.com/en/articles/11752874-chatgpt-agent ；`computer-use-preview` 2026-07-23 废弃

## 最能拉开差距的维度（证据最硬的先）

1. **A×B 交集**：既是真实登录态、又对任意 MCP agent 开放——同时满足的只有 huashu-chrome、Browser MCP（已停更）、playwright-mcp 扩展模式。要写成「和 Playwright 扩展模式二选一」，不是「独一份」。
2. **E 跨会话站点经验**：竞品里只有 Browser Use Harness 有同构能力且默认关闭、不随包分发。huashu-chrome 出厂即带 21 站已验证经验（含负面结论、带实测日期）。建议主打。
3. **H 人工交接**：三个开源 MCP 方案都没有交接工具；huashu-chrome「支付确认闸在扩展里、agent 够不着」是架构级论证。
4. **D＋G 组合**：会话隔离 + 页内标记 + 截图幕帘（agent 看不见自己的标记）同时具备的只有它。截图幕帘无任何竞品提到。
5. **F 不建议当主打**：Codex 商店文案和 Browser Use Harness 都有更硬的官方措辞。

## 必须小心的说法

1. 「Playwright MCP 只能开新的无头浏览器」已经错了：扩展模式连已登录 Chrome，还有按客户端命名着色的标签组隔离。它真实短板：无站点记忆、无人工交接、默认不是扩展模式、首次要人工选标签页。
2. chrome-devtools-mcp 的 Chrome 136 限制官方已有 `--autoConnect` 绕法（Chrome ≥ M144，chrome://inspect 逐次授权）。README 现有「❌ Chrome 136 起封了默认 profile 的远程调试」只对一半，改成「要在 chrome://inspect 里逐次授权、且只有 Chrome 144+」。
3. Browser Use Harness 在 E/F/G 上都追上来了，「只有我们有站点记忆／只有我们后台干活」站不住；改成「出厂即带 21 站已验证经验、默认开启」和「三处露出＋截图幕帘」。它的短板是 D。
4. Claude in Chrome 已 GA、全部付费套餐，不再限 Max；「API key / Bedrock 不行」仍准确。
5. 「Codex for Chrome」不是官方名（商店叫「ChatGPT」）；引官方文档「Browser isn't available in Codex CLI」比引 issue 更硬。
6. computer-use 世代已翻：Operator / ChatGPT agent 下线，`computer-use-preview` 废弃，现行 `computer_toolset_20260801`。说「读不到网络层」要补一句「Anthropic 另有 browser use tool 可以，但浏览器要自己提供、fresh profile 无凭据」。
7. 「官方未说明」的格子（Codex 的 D/G、Browser MCP 的 F、playwright-mcp 的 F）别写成 ❌。
8. huashu-chrome 的 K：README 没写定价，写「开源免费，成本＝你自己 agent 的 token」，别和竞品的现金支出并列成一个 ✅。
