# 夜间迭代记录 · 2026-08-26

一次自主迭代，从 v0.1.0 到 v0.2.0。

**方法换了**：前两轮都是被真实任务推着走，撞一个修一个。这一轮先建了一个
**本地靶场**（`test/fixtures/playground.html`，无 CSP、自带事件记录仪），
把典型交互一个个摆出来主动撞。

效果比等任务好得多——下面这些坑里有一多半，真实任务跑半年也未必碰得到，
但一碰就是**静默失效**：工具返回成功，页面其实没动。

全程只在公开测试沙箱上操作，没在任何真实站点注册账号或提交数据。
唯一读过的真实站点是知乎的一个公开问题页（只读，用来验证「curl 拿不到的站」）。

**结果**：离线测试 10/10，实景测试 19/19（新建），三个真实场景端到端跑通
（登录、注册、curl-403 站点取正文）。

## 一、最重要的三件事

### 1. 后台标签页不产生渲染帧 —— 影响面最大的一条

实测：`scrollTop` 从 0 改到 298，**scroll 事件计数是 0**；手动派发一次，懒加载立刻补货。

scroll 事件在帧生命周期里派发，而后台标签页不产帧。这和之前记录的
「X 在标签页不可见时根本不发请求」是同一个根因。

因为「不抢用户焦点」是你定的硬规则，**后台能滚动这件事必须自己兜住**：
改完 `scrollTop` 后往每个容器补发 `wheel` 和 `scroll`（scroll 在元素上不冒泡，
必须逐个发，之前只往 window 发了一次，等于没发）。

改完之后后台标签页里从 20 条滚到 100 条。

兜不住的那部分说清楚了：用 `IntersectionObserver` 判断加载时机的列表，
后台观察器根本不回调，补发事件也没用，只能 `focus:true` 切前台。
工具在高度没涨时会把三种可能一起报出来，而不是干说「滚完了」。

**同一个根因带来一个意外的好处**：Chrome 不给后台标签页弹 `alert`/`confirm`，
所以「弹窗挡死整条链路」这个经典故障，在后台工作模式下自动免疫。已写进测试。

### 2. `el.click()` 只发一个事件，真实点击发九个

真实点击浏览器依次发出
`pointerover → mouseover → mousemove → pointerdown → mousedown → focus → pointerup → mouseup → click`。

react-select、Ant Design、Element UI、MUI 的下拉全都绑在 `mousedown` 上——
只发 click，菜单永远打不开，**而且不报错**，快照里 `expanded` 一直是 false。

修的过程中连带挖出两条：

- **焦点该不该动，看 mousedown 有没有被 preventDefault。** 浏览器的规则就是这样，
  而自管焦点的组件（react-select）正是靠拦下 mousedown 再自己 focus 来打开菜单的。
  工具无条件 `focus()` 会把它刚设好的焦点抢回来。
- **事件目标应该是光标下最内层的元素**，不是 resolve 到的那个。但改完立刻踩了个更大的坑：
  **`<svg>` 元素没有 `click()` 方法**，而图标按钮的最内层几乎总是 `<svg>`/`<path>`，
  于是全网图标按钮一律 `el.click is not a function`。正解是派发合成 `click` 事件——
  规范上它会在最近的可激活祖先上执行激活行为，这正是真实点击落在 `<a>` 里的
  `<span>` 上也能跳转的原因。

### 3. `eval` 一直是死的，而文档里写错了原因

`docs/能力模型.md` 原来说「content script 的 `new Function()` 受**页面** CSP 约束」。
错的。它受的是**扩展自己的** CSP——MV3 的 content script 在隔离世界里继承扩展策略，
而扩展 CSP 一律禁 `unsafe-eval`。

怎么发现的：在**自己写的、完全没设 CSP 的本地页面**上，`eval` 照样被拦。
报错里 `script-src 'self' … chrome-extension://<uuid>` 末尾那个来源才是真相，
当初只看了前半句就下了结论。

结论方向完全变了：原来的实现不是「大站上失效」，是**哪儿都不能用**——
一个连空白页都跑不通的工具，在工具表里白占了位置。

已改为走 `chrome.scripting.executeScript({world:'MAIN'})`，那里受的才是页面 CSP，
没设 CSP 的站点能用了，大站仍然拦——那是真实且可解释的边界。

> 教训不在 CSP，在**报错信息要读完**：前半句符合预期的时候，人不会去看后半句。

## 二、新能力

### `fill` —— 一次填完整张表

`type` 每个字段都回一份完整快照，10 个字段就是 10 个来回、上万白扔的 token，
而中间那 9 份快照没有任何人读。注册/登录/下单是最常见的浏览器任务，
这条路不铺，agent 在最该用它的地方最贵。

能这么做的前提是：整批 ref 取自同一份快照，作废发生在整批之后。

一个字段失败不中止整批（中止的话 agent 只知道「第 3 个挂了」，前后状态全靠猜），
但**有字段失败时会跳过 submit**——不替用户交一份残表。

### `key` —— 键盘

之前完全没有，注册/登录流程走不完：Esc 关不掉弹窗、Tab 跳不了字段、
自定义下拉的方向键选不中。

实现时最要紧的一件事：**合成的 KeyboardEvent 不产生任何默认行为**。
只派发事件的实现在简单页面上「看起来能用」（那些页面恰好自己监听了 keydown），
一碰到依赖浏览器原生行为的表单就静默失效。所以 `key` 做两件事：
派发事件 + 把默认行为补上（Tab 移焦点、Enter 提交/点击、Backspace 删字符、
Ctrl+A 全选、可打印字符插入、Esc 关 `<dialog>`）。补之前先看有没有 `preventDefault`。

两个顺手的设计：收数组一次按一串（`["Tab","Tab","Enter"]`）；认 `"ctrl+a"` 写法
（agent 生成这个的概率远高于 `{key:"a",mods:["ctrl"]}`，就着它的习惯来）。
`keyCode` 一起发——国内老站到今天还在读 `e.keyCode`。

### iframe 支持

支付、验证码、OAuth、嵌入式编辑器几乎全在 iframe 里，之前一个都够不着。

现在注入走 `allFrames: true`，子框架元素在快照里写成 `e5@f2`，桥接层按后缀路由、
把 ref 还原、换上那个框架自己的 snapshotId。

**agent 面对的协议一点没变**——content script 不知道有框架这回事，
`click`/`type`/`fill`/`key` 一行都没改。跨源 iframe 同样有效（已测）。

### 拖放上传

`upload` 原来只认 `<input type=file>`，找不到就报错。但 X 的 Article、Notion、语雀
这类编辑器**页面上根本不存在 file input**，只监听拖放——等于把「往文章里插图」
这一整类任务判了死刑。

现在传 `dropSelector` 就走拖放。要点是**整套 drag 事件都要发**：很多实现在
`dragover` 里才 `preventDefault` 来「认领」这次拖放，只发 drop 的话浏览器会按
默认行为处理（在新标签页打开这个文件）。返回值里会说明页面有没有认领，
没认领就是拖错了地方——这比「成功了但什么都没发生」有用得多。

## 三、快照质量

一次登录页从 7 个元素降到 4 个，名字一个没少：

- `<button>` 里的 `<i class="fa"> Login</i>` 靠 `cursor:pointer` 混成第二个候选
- `<label for=x>` 是输入框的代言人，本尊在场就不该再列

这类重复不只是费 token，**它给了 agent 一个点了不管用的选项**。
区分「弱候选」（只靠 `cursor:pointer` 进来的）很重要——带 `onclick`/`tabindex`
的元素即使嵌在链接里也可能是独立操作（卡片上的「×」），丢了就没了。

**字段命名**补了三条，demoqa 那张出了名难搞的注册表现在每个字段都有正确名字：

| 问题 | 修法 |
|---|---|
| `input[type=file]` 标成 textbox | 单列 `file` 角色。agent 看见 textbox 就去 type，而往 file input 写字符串什么都不会发生 |
| react-select 的 combobox 没名字 | 占位符挂在 `aria-describedby` 上 |
| 标签和输入框并排但没写 `for` | 就近查找兜底（只给表单控件用，链接和按钮不捡旁边的标签，否则造出假名） |

**新增「⚠️ 页面提示」段**，收 `role=alert`/`aria-live`/error 类节点，顶到快照最上面。
表单流程最主要的失败模式是校验错误，而它常在长页面下方，正文节选截不到——
没有这一段，「已提交」和「提示手机号格式不对」在 agent 眼里长得一模一样。

（第一版有误报，把 Bootstrap 的 `.alert` 推广框当成了校验错误。现在
`role`/`aria` 声明的无条件采信，靠 class 名猜中的要过滤导航区和纯链接块。）

## 四、基础设施：三个静默故障

1. **桥是长驻单例，永远跑着旧代码。** 发现时它已经跑了 8 小时，`bridge.json` 写着
   `0.1.0`，磁盘上的代码早改过。用户 `npm update` 之后桥岿然不动，症状是「改了没用」，
   **不报任何错**。修：版本号收敛到 `package.json` 单一真源，连接前比对，
   不一致就 SIGTERM 换代；桥补了 SIGTERM 处理，退出前把在途命令回成明确错误
   （不做的话 agent 干等 60s 超时，用户看到的是「卡住」不是「重启了」）。

2. **扩展掉线后最长等 30 秒才重连**，全靠 alarm 兜底。桥一换代，接下来一分钟
   所有命令都是 `NO_EXTENSION`。修：`onclose` 立刻重连，指数退避 0.5s→15s。

3. **扩展重载会丢掉受控标签页**（`storage.session` 被清空）。改存 `local`，
   读的时候用 `chrome.tabs.get` 校验——用「读时校验」换「跨重载不丢」。

另外补了 `BridgeClient.close()`。之前没有，一条开着的 WebSocket 会把进程永远吊住。

## 五、安全：回执把密码原样印出来了

注册流程实测时看到：

```
已填 3/3：e17="hc_probe"，e18="Passw0rd!123"，…
```

脱敏只按长度截断（>12 字符才截），而真实密码常常正好十来位，一个 12 位的密码
完完整整印在回执里——**而回执会进 agent 的上下文，也会落进审计日志**。

修：密码按**输入框类型**判断，跟长度无关（`type=password`，或 name/id/autocomplete
里带 pass/pwd/secret/token/cvv/验证码 一类词），一律显示 `<已填 N 位，内容不回显>`。

顺带补了审计日志的两个漏洞：`redact()` 只脱敏 `text`，而 `fill` 的整张表在 `fields` 里
（密码、验证码、身份证号全在那儿）；`upload` 的 base64 进日志等于把文件抄一遍。

## 六、顺手修的

- `<select>` 的名字变成了所有选项拼接（"请选择 昆明 深圳"）——`innerText` 对 select
  返回全部选项，排除掉。
- 往非输入框写值时报 `Illegal invocation`，这句话对 agent 毫无信息量，
  它只会换个 ref 继续瞎试。改成说清楚「目标是 `<a>`，不是输入框，多半是快照过期了」。
- `read_text` 清掉零宽字符和头像小图。知乎一页从 24.6KB / 568 行降到 21.9KB / 406 行，
  27 张头像图全清，正文完整。零宽字符在国内站点遍地都是，会变成一行行看不见内容的
  「文字」，还破坏空行折叠。
- `click` 的 schema 里声明了 `button: left/middle/right`，**从来没实现过**。
  右键弹的是浏览器原生菜单（扩展够不着），中键开新标签页用 `tabs` 更直接。
  删掉——schema 承诺做不到的事，比没有更糟。
- `query` 的 `@value` / `@checked` 取的是 HTML 特性而非当前属性——抓一张已填好的表
  会静默返回一片空，而「空」看着像「这个字段本来就没填」。
- 删掉 content 侧已成死代码的 `doEval`（eval 改走 MAIN world 之后就没人调它了）。
- `install` 把 `~/.claude/mcp.json` 当成一个叫「claude」的新 agent 重复列出。
  排除范围改用表里**所有候选路径**算，不只是命中的那个。
- `install` 输出的中文名列不对齐（`padEnd` 数码元，CJK 占两格）。
- 测试卫生：`mcp.test.js` 断言失败时 `client.close()` 跑不到，子进程泄漏，
  `node --test` 永远不退出——症状是「卡住」不是「失败」，排查成本天差地别。改用 try/finally。

## 七、留给你决定的

1. **`chrome.debugger`（L2）仍未实现。** 目前全部能力走 L1，好处是没有黄色调试条、
   商店审核压力小。真正需要 L2 的场景我今晚没撞到，但存在：需要真实可信输入事件的
   反自动化站点、网络请求拦截改写。要不要加，取决于你想不想要那条黄带子。

2. **`times` 的默认值。** `scroll` 默认只滚 1 次，要加载更多必须显式传 `times`。
   我没改默认值（改了会让「轻轻滚一下」变贵），而是让工具在高度没涨时明确提示。
   如果你觉得 agent 还是会忘，可以把 `to:"bottom"` 的默认改成 5。

3. **实景测试需要 Chrome 开着**，所以 `npm test` 和 `npm run test:live` 分开了。
   CI 只能跑前者。要不要引入 headless Chrome 跑后者，是个成本问题。

4. 之前挂着的两个小红书分析决策仍未回：涨粉看**效率**还是**绝对数**，
   以及「身份可信度」那条路缺 24 小时先行指标。

## 八、这次迭代方法本身的收获

**主动造场景比等真实任务有效得多**，因为这类 bug 的共同点是静默——
真实任务里你看到的是「agent 绕了个远路完成了」，不是「工具坏了」。

靶场的关键设计是**事件记录仪**：把真实到达的事件连同 `isTrusted`、`target`、
`defaultPrevented` 一起记下来。react-select 那个问题我先猜了四轮都不对
（猜 React 收不到事件、猜焦点被抢、猜事件目标不对），架起记录仪之后一次就定位了。

**下次遇到「看着该通却不通」，先造观测点，别接着猜。**
