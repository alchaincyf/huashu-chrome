# ref 快照长什么样

`snapshot` 把当前页拍成一份带编号的可交互元素清单，一页通常 1–2k token。
agent 之后所有的操作都按编号说话。

```
# 淘宝网 — https://www.taobao.com
[snapshot s2] 38 个可交互元素

[e1]  link      "首页"
[e2]  searchbox "搜索商品" (empty)
[e3]  button    "搜索"
[e4]  checkbox  "包邮" (unchecked)
```

agent 说「点 e3」，不说「点坐标 (420, 88)」也不说「点 `.btn-search > span`」。
**坐标会漂，selector 会因改版全崩，ref 两样都不会。**

元素后面跟着的括号是状态：`value` / `checked` / `selected` / `expanded` / `disabled`，
以及那些只靠 class 表达的状态。没有它，「勾上了没有」这类问题只能靠截图猜。

## iframe

iframe 里的元素编号带 `@fN` 后缀：

```
[e5@f2] button "确认支付"
```

照原样传给任何工具即可，路由是自动的，**跨源也有效**——支付、验证码、OAuth
恰好都在 iframe 里。

## 弹窗、站方声明的工具、页面提示，各自单列

`[role=dialog]` 一类的浮层文字放在 `🪟` 段。

页面用 WebMCP 声明式表单（`<form toolname tooldescription>`，Chrome 149 起 origin trial）
自述「这个表单干什么、每个字段填什么」时，放在 `🔧` 段并标出各字段的 ref
——**站方自己写的参数说明比猜字段准**。

页面提示单列一段：

```
⚠️ 页面提示：
  · 手机号格式不正确，请填写 11 位数字
```

表单流程最主要的失败模式是校验错误，而它常常在长页面的下方。
没有这一段，「已提交」和「被校验拦下」在 agent 眼里长得一模一样。

## 快照会过期

页面跳转、DOM 变了之后，任何按旧 ref 的操作都会被拒绝并要求重拍。
宁可多花一次 `snapshot`，也不能让 agent 在你的真实登录态下点错东西。

批处理里定位元素因此有两种写法，规则很简单：**页面结构没变时用快照编号，
变了之后用名字**（`{role:"button", name:"下一步"}`）。后者在页面重新渲染后现场查找，
所以走流程时它才是对的那个。名字撞车时工具会列出候选让你选，不会替你猜
——「删除」和「删除全部」常常并排放着。
